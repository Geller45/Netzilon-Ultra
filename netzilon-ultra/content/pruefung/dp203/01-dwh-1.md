## Quiz

? Eine Tabelle `DimEmployee` in einem dedizierten Synapse-SQL-Pool hat die Spalten `EmployeeKey int IDENTITY(1,1) NOT NULL`, `EmployeeID int NOT NULL`, `FirstName`, `LastName`, `JobTitle`, `LastHireDate`, `StreetAddress`, `City`, `StateProvince`, `Portalcode`. Anforderungen: Benutzer sollen den aktuellen Vorgesetzten (Manager) eines Mitarbeiters ermitteln können, eine unternehmensweite Berichtshierarchie soll möglich sein und Attribute des Managers (Name, Berufsbezeichnung) sollen schnell nachschlagbar sein. Welche Spalte fügen Sie hinzu?
- [ManagerEmployeeID] [smallint] NULL
- [ManagerEmployeeKey] [smallint] NULL
* [ManagerEmployeeKey] [int] NULL
- [ManagerName] [varchar](200) NULL
! Selbstreferenz auf den Surrogatschlüssel: Die neue Spalte muss denselben Datentyp wie `EmployeeKey` (int) haben, damit über einen Self-Join die Manager-Attribute gefunden werden. Dozent: Frage 1 der SQL-Prüfungsfragen.
@ DP-203 Frage 1

? Sie entwerfen einen dedizierten Synapse-SQL-Pool. Anforderungen: einen Mitarbeiterdatensatz zu einem bestimmten Zeitpunkt zurückgeben, die neuesten Mitarbeiterinformationen pflegen, Abfragekomplexität minimieren. Wie modellieren Sie die Mitarbeiterdaten?
- als temporale Tabelle (Zeittafel)
- als SQL-Graphtabelle
- als degenerierte Dimensionstabelle
* als Slowly Changing Dimension (SCD) Typ 2
! SCD Typ 2 versioniert Dimensionszeilen mit Surrogatschlüssel, Gültigkeitszeitraum (StartDate/EndDate) und ggf. IsCurrent-Flag – damit sind historische und aktuelle Stände abfragbar. (Temporale Tabellen werden in dedizierten SQL-Pools nicht unterstützt.)
@ DP-203 Frage 12

? Faktentabelle FactPurchase (dedizierter SQL-Pool) mit PurchaseKey bigint, DateKey int, SupplierKey int, StockItemKey int, PurchaseOrderID int NULL, OrderedQuantity, OrderedOuters, ReceivedOuters, Package nvarchar(50), IsOrderFinalized bit, LineageKey; täglich 1 Mio. neue Zeilen, Daten für 3 Jahre. Täglich läuft: `SELECT SupplierKey, StockItemKey, IsOrderFinalized, COUNT(*) FROM FactPurchase WHERE DateKey >= 20210101 AND DateKey <= 20210131 GROUP BY SupplierKey, StockItemKey, IsOrderFinalized`. Welche Verteilung minimiert die Abfragezeit?
- repliziert
* hashverteilt auf PurchaseKey
- Round-Robin
- hashverteilt auf IsOrderFinalized
! Große Faktentabelle → Hash-Verteilung auf einer Spalte mit vielen eindeutigen Werten, ohne NULLs und ohne Datumsspalte. PurchaseKey verteilt gleichmäßig auf die 60 Verteilungen; IsOrderFinalized (bit) hätte nur 2 Werte → massiver Skew.
@ DP-203 Frage 20

? Für Lieferantendaten (SupplierSystemID = eindeutige ID im ERP, SupplierName, Adressfelder, City, StateProvince, Country, PostalCode, Description, Category) soll in einem dedizierten SQL-Pool eine SCD Typ 2 entstehen. Welche DREI Spalten fügen Sie hinzu?
* Surrogat-Primärschlüssel (Ersatzschlüssel)
* Gültig-ab-Datum (Effective Start Date)
- Geschäftsschlüssel (Business Key)
- Datum der letzten Änderung
* Gültig-bis-Datum (Effective End Date)
- Fremdschlüssel
! Den Geschäftsschlüssel gibt es schon (SupplierSystemID). Für Typ 2 braucht man einen Surrogatschlüssel (mehrere Versionen pro Lieferant) sowie Start- und Enddatum. Die Sammlung nennt BCE, Community 87 % ABE.
@ DP-203 Frage 34

? FactPurchase (PurchaseKey bigint, DateKey int, SupplierKey, StockItemKey, PurchaseOrderID NULL, Mengen, Package, IsOrderFinalized bit, LineageKey) erhält täglich 1 Mio. Zeilen, Daten für 3 Jahre. Täglich: `SELECT SupplierKey, StockItemKey, COUNT(*) FROM FactPurchase WHERE DateKey >= 20210101 AND DateKey <= 20210131 GROUP BY SupplierKey, StockItemKey`. Welche Verteilung minimiert die Abfragezeiten?
- repliziert
* hashverteilt auf PurchaseKey
- Round-Robin
- hashverteilt auf DateKey
! Keine Datumsspalte als Verteilungsschlüssel: Alle Zeilen eines Datums landen in derselben Verteilung, bei Monatsfiltern arbeiten nur wenige der 60 Verteilungen. PurchaseKey verteilt gleichmäßig.
@ DP-203 Frage 39

? Für einen Personal-Data-Mart liegt ein flacher Extrakt mit EmployeeID, FirstName, LastName, Recipient, GrossAmount, TransactionID, GovernmentID, NetAmountPaid, TransactionDate vor. Welche ZWEI Tabellen erstellen Sie im Sternschema (dedizierter SQL-Pool)?
- eine Dimensionstabelle für Transaction
- eine Dimensionstabelle für EmployeeTransaction
* eine Dimensionstabelle für Employee
- eine Faktentabelle für Employee
* eine Faktentabelle für Transaction
! Beschreibende, selten geänderte Attribute (Name, GovernmentID) → Dimension Employee; messbare Ereignisse (Beträge, Datum) → Faktentabelle Transaction, verbunden über EmployeeID.
@ DP-203 Frage 42

? Eine Dimensionstabelle soll die Werte der Attribute im Zeitverlauf verfolgen und den Verlauf erhalten, indem bei Änderungen neue Zeilen hinzugefügt werden. Welchen SCD-Typ verwenden Sie?
- Typ 0
- Typ 1
* Typ 2
- Typ 3
! Typ 2 = neue Zeile je Version (Surrogatschlüssel, Start-/Enddatum, IsCurrent). Typ 1 überschreibt, Typ 3 speichert den Vorwert in einer zusätzlichen Spalte, Typ 0 ändert nie.
@ DP-203 Frage 43

? Für Produktkategoriedaten soll in DimProduct (ProductKey IDENTITY, ProductSourceID, ProductName, Color, SellStartDate, SellEndDate, RowInsertedDateTime, RowUpdatedDateTime, ETLAuditID) eine SCD Typ 3 umgesetzt werden. Welche ZWEI Spalten fügen Sie hinzu?
- [EffectiveEndDate] [datetime] NULL
* [CurrentProductCategory] [nvarchar](100) NOT NULL
- [ProductCategory] [nvarchar](100) NOT NULL
- [EffectiveStartDate] [datetime] NOT NULL
* [OriginalProductCategory] [nvarchar](100) NOT NULL
! Typ 3 speichert zwei Versionen eines Attributs als getrennte Spalten (aktueller und ursprünglicher/vorheriger Wert) statt neuer Zeilen. Gültigkeitsdaten gehören zu Typ 2.
@ DP-203 Frage 59

? Eine Dimensionstabelle in Synapse ist kleiner als 1 GB. Anforderungen: schnellste Abfragezeit, minimale Datenverschiebung bei Abfragen. Welcher Tabellentyp?
* repliziert
- hashverteilt
- Heap
- Round-Robin
! Replizierte Tabellen liegen vollständig auf jedem Compute-Knoten – Joins brauchen keine Datenverschiebung. Empfehlung bis ca. 2 GB komprimiert.
@ DP-203 Frage 66

? Für eine Dimensionstabelle in einem dedizierten SQL-Pool soll ein Surrogatschlüssel (Ersatzschlüssel) mit schnellster Abfrageleistung entstehen. Was verwenden Sie?
- eine GUID-Spalte
- ein Sequenzobjekt
* eine IDENTITY-Spalte
! IDENTITY erzeugt int-/bigint-Surrogatschlüssel ohne Ladeeinbußen; Sequenzobjekte gibt es im dedizierten Pool nicht, GUIDs sind groß und schlecht für Joins. (Achtung: IDENTITY-Werte sind wegen der 60 Verteilungen nicht lückenlos.)
@ DP-203 Frage 67

? DimCustomer (dedizierter SQL-Pool, REPLICATE, CCI) hat u. a. CustomerKey, CustomerSourceID, Name- und Kontaktspalten, InsertedDate, ModifiedDate, HashKey und IsCurrentRow. Welche ZWEI Spalten fehlen für eine SCD Typ 2?
- [HistoricalSalesPerson] [nvarchar](256) NOT NULL
* [EffectiveEndDate] [datetime] NOT NULL
- [PreviousModifiedDate] [datetime] NOT NULL
- [RowID] [bigint] NOT NULL
* [EffectiveStartDate] [datetime] NOT NULL
! Typ 2 braucht einen Gültigkeitszeitraum (Start- und Enddatum); IsCurrentRow und Surrogatschlüssel sind bereits vorhanden. Die Sammlung nennt BD, die Community 70 % BE.

## Zuordnen

### DP-203 Frage 9 (Hotspot): Sternschema – alle Dimensionstabellen < 2 GB komprimiert und fast statisch, Faktentabelle Fact_DailyBookings ca. 6 TB. Welcher Tabellentyp je Tabelle?
- Dim_Customer => Repliziert (Replicated)
- Dim_Employee => Repliziert (Replicated)
- Dim_Time => Repliziert (Replicated)
- Fact_DailyBookings => Hashverteilt (Hash distributed)

### DP-203 Frage 19 (Hotspot): Stagingtabelle in Synapse – täglich ca. 1 Mio. Zeilen aus Blob Storage, Tabelle wird vor jedem Laden geleert. Ladedauer minimieren.
- Verteilung (Distribution) => Round-robin
- Indizierung (Indexing) => Heap
- Partitionierung (Partitioning) => None (keine)

### DP-203 Frage 21 (Hotspot): Sternschema mit 4 Tabellen (inkl. Datumsdimension) für Website-Analysedaten (Date, EventCategory, EventAction, EventLabel, ChannelGrouping, TotalEvents, UniqueEvents, SessionWithEvents). In welche Tabelle gehört jede Spalte?
- EventCategory => DimEvent
- ChannelGrouping => DimChannel
- TotalEvents => FactEvents

### DP-203 Frage 35 (Hotspot): Migration einer SQL-Server-Datenbank in 3. Normalform zu einem Sternschema im dedizierten SQL-Pool; Dimensionstabellen sollen Lesevorgänge optimieren.
- Daten für Dimensionstabellen transformieren durch => Denormalisieren auf die 2. Normalform
- Primärschlüsselspalten der Dimensionstabellen => neue IDENTITY-Spalten (Surrogatschlüssel)

### DP-203 Frage 38 (Hotspot): `CREATE TABLE DimProduct (ProductKey int IDENTITY(1,1) NOT NULL, ProductSourceID int NOT NULL, ProductName, ProductNumber, Color, Size, Weight, ProductCategory, SellStartDate date NOT NULL, SellEndDate date NULL, RowInsertedDateTime datetime NOT NULL, RowUpdatedDateTime datetime NOT NULL, ETLAuditID int NOT NULL)` – vervollständigen Sie die Aussagen.
- DimProduct ist eine SCD vom => Typ 1 (es gibt keine Gültigkeitsspalten, Zeilen werden per RowUpdatedDateTime überschrieben; die Sammlung nennt Typ 2, Community Typ 1)
- Die Spalte ProductKey ist => ein Surrogatschlüssel (IDENTITY; die Sammlung nennt „Geschäftsschlüssel“ – das ist ProductSourceID)

### DP-203 Frage 60 (Drag & Drop): pool1 – Common.Date (7.300 Zeilen, jährlich neue Zeilen), Marketing.WebSessions (1,5 Mrd. Zeilen, stündliche Inserts/Updates, Faktentabelle), Staging.WebSessions (300.000 Zeilen, stündlich geleert und neu befüllt). Laden in Staging maximieren, Berichtsabfragen minimieren.
- Common.Date => Repliziert

### DP-203 Frage 61 (Hotspot): FactInternetSales (100 Mio. Zeilen; Abfragen aggregieren SalesAmount und OrderQuantity des letzten Jahres für ein bestimmtes Produkt) – Datengröße und Abfragezeit minimieren. `CREATE TABLE … WITH ([1], DISTRIBUTION = [2])`
- [1] Index => CLUSTERED COLUMNSTORE INDEX
