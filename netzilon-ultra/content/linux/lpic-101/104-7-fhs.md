## Profi

### Lernziel (Gewicht 2)
Den **Filesystem Hierarchy Standard (FHS)** kennen und Dateien mit `find`, `locate`, `which`, `whereis`, `type` finden.

### FHS – wichtige Verzeichnisse
| Pfad | Inhalt |
|---|---|
| `/` | Wurzel |
| `/bin`, `/sbin` | essenzielle Programme (heute meist Link auf `/usr/bin`, `/usr/sbin`) |
| `/boot` | Kernel, initramfs, Bootloader |
| `/dev` | Gerätedateien |
| `/etc` | systemweite **Konfiguration** (Text) |
| `/home`, `/root` | Heimverzeichnisse, root-Home |
| `/lib`, `/lib64` | Bibliotheken, Kernelmodule |
| `/media`, `/mnt` | Wechselmedien / temporäre Mounts |
| `/opt` | optionale Fremdsoftware |
| `/proc`, `/sys` | virtuell: Prozesse/Kernel, Geräte |
| `/run` | Laufzeitdaten seit Boot |
| `/srv` | Daten von Diensten (Web, FTP) |
| `/tmp` | temporär (Sticky, bei Boot oft geleert), `/var/tmp` bleibt erhalten |
| `/usr` | Programme, Bibliotheken, Doku (`/usr/bin`, `/usr/share`, `/usr/local`) |
| `/var` | variable Daten: `log`, `spool`, `cache`, `lib`, `mail` |
- **Shareable vs. unshareable**, **static vs. variable** – Grundprinzip der Trennung.

### Dateien finden
- **`find pfad [Tests] [Aktionen]`**: `-name`, `-iname`, `-type f|d|l`, `-size +10M`, `-mtime -7` (jünger als 7 Tage), `-mmin`, `-atime`, `-user`, `-group`, `-perm 644`/`-perm -4000`, `-newer datei`, `-maxdepth`; Aktionen `-print`, `-delete`, `-exec cmd {} \;`, `-exec cmd {} +`, `-ok`. Operatoren `-and`, `-or`, `!`.
- **`locate name`**: schnelle Suche in der Datenbank (`/var/lib/mlocate/mlocate.db`), aktualisiert mit **`updatedb`** (täglich per cron); neue Dateien erscheinen erst nach `updatedb`.
- **`which`** (Programm im PATH), **`whereis`** (Binary, Man-Page, Quellen), **`type`** (Shell: Alias/Builtin/Datei).

## Einfach

Linux ist wie ein **gut sortiertes Haus**, in dem jeder Gegenstand einen festen Platz hat – das nennt man den **FHS** (Filesystem Hierarchy Standard). Wer ihn kennt, findet alles:

- `/etc` ist der **Schaltkasten** mit allen Einstellungen.
- `/home` sind die **Zimmer der Bewohner**, `/root` das Zimmer des Chefs.
- `/var` ist der **Briefkasten und das Archiv**: Logs, Mails, Datenbanken (alles, was sich verändert).
- `/usr` ist die **Werkzeugwerkstatt** mit den Programmen.
- `/tmp` ist der **Schmierzettelkorb**, `/boot` die **Startrampe**, `/dev` die **Steckdosenleiste** für Geräte und `/mnt` oder `/media` die **Anbauten** für Laufwerke.
- `/proc` und `/sys` sind **Fenster in das Gehirn des Kernels** – sie sind keine echten Ordner auf der Platte.

Wenn du etwas nicht findest, hast du zwei Suchhelfer: **`find`** läuft wirklich durch alle Ordner und prüft Name, Größe, Alter oder Besitzer – gründlich, aber langsam. **`locate`** schaut in ein **Telefonbuch**, das jede Nacht neu gedruckt wird (`updatedb`) – blitzschnell, aber eventuell veraltet.

Für Programme gibt es eine Abkürzung: `which ls` sagt dir, welche Datei läuft, wenn du `ls` tippst. `whereis` zeigt zusätzlich die Hilfeseiten. Und mit `find ... -exec` kannst du mit jedem Fund gleich etwas tun, z. B. löschen oder packen.

## Merksatz
- **/etc Einstellungen, /var Veränderliches, /usr Programme, /home Benutzer.**
- **find = live und gründlich, locate = Datenbank und schnell.**
- **updatedb aktualisiert locate.**
- **which = PATH, whereis = Binary+Man, type = Shell.**
- **/tmp = temporär, /opt = Fremdsoftware, /srv = Daten der Dienste.**

## Prüfungsfalle
- `/bin`, `/sbin`, `/lib` sind auf modernen Systemen oft **Links** nach `/usr/...`.
- `locate` findet **neue** Dateien erst nach `updatedb`.
- `find -mtime -7` = **innerhalb** der letzten 7 Tage, `+7` = älter, `7` = genau vor 7 Tagen.
- `-size +10M` (mehr als 10 MiB); `-size 10M` exakt.
- `-exec … {} \;` (je Datei ein Aufruf) vs. `{} +` (gebündelt).
- `/proc` und `/sys` belegen keinen Plattenplatz.
- `/mnt` temporär, `/media` automatisch für Wechselmedien.
- `/tmp` kann beim Boot geleert werden, `/var/tmp` nicht.

## Grafik

### find vs. locate
1. Benutzer -> find: find /etc -name "*.conf" -mtime -1
2. find -> Dateisystem: durchläuft Verzeichnisbaum live
3. find -> Benutzer: aktuelle Treffer
4. cron -> updatedb: nachts Datenbank neu aufbauen
5. Benutzer -> locate: locate sshd_config
6. locate -> Benutzer: schnelle Antwort aus der Datenbank

## Lab
**Maschine**: debian01.
```bash
# auf debian01
ls /
find /etc -name "*.conf" -mtime -7 2>/dev/null | head
find /var/log -type f -size +1M
find /tmp -user $(whoami) -type f
find . -name "*.bak" -exec ls -l {} \;
find /home -perm -4000 2>/dev/null
sudo updatedb; locate sshd_config
which ls; whereis ssh; type cd
```

## Befehle
- `find / -name datei` – nach Name
- `find . -type f -size +10M` – große Dateien
- `find . -mtime -1` – neu seit gestern
- `find . -exec cmd {} \;` – Aktion je Fund
- `locate name` – Datenbanksuche
- `updatedb` – Datenbank aktualisieren
- `which cmd` – Programmpfad
- `whereis cmd` – Binary, Man, Quelle
- `type cmd` – Befehlsart

## Karteikarten
- F: Was liegt in /etc? | A: Systemweite Konfigurationsdateien.
- F: Was liegt in /var? | A: Variable Daten wie Logs, Spool, Mail, Caches.
- F: Wofür ist /opt? | A: Optionale, eigenständige Fremdsoftware.
- F: Was ist /proc? | A: Virtuelles Dateisystem mit Prozess- und Kernelinformationen.
- F: Was macht updatedb? | A: Baut die locate-Datenbank neu auf.
- F: Was bedeutet find -mtime +7? | A: Vor mehr als 7 Tagen geändert.
- F: Unterschied which/whereis? | A: which sucht im PATH, whereis auch Man-Pages und Quellen.
- F: Wofür ist /srv? | A: Daten, die von Diensten bereitgestellt werden.
- F: Was ist /run? | A: Laufzeitdaten seit dem Boot (tmpfs).
- F: Was bewirkt -exec {} +? | A: Übergibt mehrere Treffer gebündelt an einen Befehl.
