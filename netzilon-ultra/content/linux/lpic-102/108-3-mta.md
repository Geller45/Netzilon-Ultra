## Profi

### Lernziel (Gewicht 3)
Die Funktion eines MTA verstehen, `mail`/`mailq`/`newaliases` verwenden und die gängigen MTAs (**Postfix**, **Exim**, **sendmail**) unterscheiden.

### Begriffe
- **MUA** (Mail User Agent): Mailprogramm des Benutzers (`mail`, `mutt`, Thunderbird). **MTA** (Mail Transfer Agent): überträgt Mails per **SMTP** (Port 25; Submission 587; SMTPS 465). **MDA** (Mail Delivery Agent): stellt in das Postfach zu (`procmail`, `dovecot-lda`). Abruf durch Client via **IMAP** (143/993) oder **POP3** (110/995).
- Lokale Postfächer: `/var/mail/<user>` oder `/var/spool/mail/<user>` (mbox) bzw. `~/Maildir`.

### MTAs
- **sendmail** (historisch, `/etc/mail/sendmail.cf`/`sendmail.mc`), **Postfix** (modular, `/etc/postfix/main.cf`, `master.cf`, `postconf -n`, `postfix reload`), **Exim** (Debian-Standard früher, `/etc/exim4/`, `update-exim4.conf`), **qmail**. Alle bieten ein sendmail-kompatibles Binary `/usr/sbin/sendmail`; `mail` nutzt es zum Versand.

### Aliase und Weiterleitung
- `/etc/aliases`: `root: philipp` oder `team: a, b`. Nach Änderung **`newaliases`** (bzw. `sendmail -bi`) ausführen, damit die Datenbank (`aliases.db`) neu erzeugt wird.
- `~/.forward`: Weiterleitung pro Benutzer, z. B. eine Adresse oder `|programm`.

### Mail-Queue
- `mailq` bzw. `sendmail -bp` / `postqueue -p`: wartende Mails. `postqueue -f` oder `sendmail -q` erzwingt Zustellung; `postsuper -d ID` löscht. Logs: `/var/log/mail.log`, `mail.err`.

### Test
`echo "Text" | mail -s "Betreff" user@example.com`. Mit `mail` ohne Argument liest man lokale Post.

## Einfach

Eine E-Mail ist wie ein **Brief**. Du schreibst ihn am Computer (das ist der **MUA**, dein Mailprogramm). Dann braucht er eine **Post**, die ihn weiterträgt: Das ist der **MTA**. Er nimmt den Brief, schaut auf die Adresse und gibt ihn dem nächsten Postamt weiter, bis er beim richtigen Server ankommt. Dort legt ein **MDA** ihn in den Briefkasten des Empfängers. Der Empfänger holt ihn später per IMAP oder POP3 ab.

Die Sprache der Post heißt **SMTP**. Unter Linux gibt es mehrere Postämter zur Auswahl: **Postfix** (heute am häufigsten), **Exim** und das alte **sendmail**. Alle verstehen den Befehl `sendmail`, damit Programme einfach Briefe aufgeben können.

Ein **Alias** ist ein Zweitname: In `/etc/aliases` steht `root: philipp`. Dann landet alle Post an „root“ bei Philipp. Wichtig: Nach jeder Änderung musst du `newaliases` ausführen, sonst liest das System noch die alte Liste.

Wenn eine Mail nicht rausgeht, wartet sie in der **Warteschlange** (Queue). Mit `mailq` siehst du, was dort hängt, und kannst es erneut versuchen lassen.

## Merksatz
- **MUA schreibt, MTA transportiert, MDA liefert aus.**
- **Aliases ändern → `newaliases`.**
- **SMTP 25, Submission 587, IMAP 143, POP3 110.**
- **`mailq` zeigt die Warteschlange.**

## Prüfungsfalle
- Ohne `newaliases` bleibt die Änderung in /etc/aliases wirkungslos.
- IMAP/POP3 sind **Abruf**-, SMTP ist **Versand**protokoll.
- `.forward` liegt im Home des Benutzers und braucht keinen Neustart.
- Postfix-Konfiguration: `main.cf`, nicht `sendmail.cf`.

## Grafik

### Weg einer E-Mail
1. Absender-MUA -> MTA: Mail per SMTP einliefern
2. MTA -> Ziel-MTA: Mail per SMTP (Port 25) weiterreichen
3. Ziel-MTA -> MDA: Zustellung an Postfach
4. MDA: Mail liegt in /var/mail/user oder Maildir
5. Empfänger-MUA -> MDA: Abruf per IMAP

## Lab
**Maschine**: debian01 mit Postfix.
```bash
sudo apt install postfix mailutils
echo "Hallo" | mail -s "Test" root
sudo mailq
sudo tail /var/log/mail.log
echo "root: philipp" | sudo tee -a /etc/aliases && sudo newaliases
postconf -n
```

## Befehle
- `mail -s "Betreff" user` – Mail senden
- `mailq` – Warteschlange anzeigen
- `newaliases` – Alias-Datenbank neu bauen
- `postconf -n` – Postfix-Konfiguration anzeigen
- `postqueue -f` – Queue sofort abarbeiten
