## Profi

### Warum IPv6?
| | IPv4 | IPv6 |
|---|---|---|
| Länge | 32 Bit | **128 Bit** (8 Blöcke à 16 Bit) |
| Adressen | 2³² ≈ 4,3 Mrd. | 2¹²⁸ ≈ 3,4 × 10³⁸ |
| Schreibweise | dezimal, Punkte | **hexadezimal**, Doppelpunkte |
| Autokonfiguration | DHCP / APIPA | **SLAAC**, DHCPv6 |
| Adressauflösung | ARP (Broadcast) | **NDP** (Neighbor Discovery, ICMPv6-Multicast) |
| Broadcast | ja | **nein** – ersetzt durch Multicast |
| IPsec | optional | im Standard vorgesehen (Unterstützung verpflichtend, Nutzung optional) |
| Header | variabel, Prüfsumme | fester 40-Byte-Basisheader, **keine Prüfsumme**, Extension Header → Router verarbeiten schneller |
| Fragmentierung | durch Router | **nur durch den Sender** (Path MTU Discovery) |
| NAT | notwendig | nicht nötig (Ende-zu-Ende-Adressierung) |
| QoS | ToS-Feld | Traffic Class + **Flow Label** |
| DNS | A-Record | **AAAA-Record**, Reverse-Zone **ip6.arpa** |
Windows nutzt IPv6 seit Vista **parallel** zu IPv4 (**Dual Stack**) und bevorzugt es.

### Kontroverse bei der Einführung
- **Datenschutz**: Wird die Interface-ID aus der MAC-Adresse gebildet (**EUI-64**), ist ein Gerät weltweit wiedererkennbar → Gegenmittel **Privacy Extensions** (zufällige, wechselnde Adressen, in Windows Standard).
- **Sicherheitsbedenken**: Wegfall von NAT als „Schutzschicht“, Geräte direkt erreichbar → Firewall zwingend; Admins kennen IPv6 schlechter.
- **Aufwand/Kosten**: Umstellung von Hardware, Software, Know-how; Dual Stack verdoppelt den Pflegeaufwand; viele Provider/Anwendungen unterstützen IPv6 nur teilweise.

### Schreibweise und Kürzung
Ausgeschrieben: `2001:0DB8:3FA9:0000:0000:0000:00D3:9C5A`
1. **Führende Nullen** jedes Blocks weglassen → `2001:DB8:3FA9:0:0:0:D3:9C5A`
2. **Eine** zusammenhängende Folge von Null-Blöcken durch **`::`** ersetzen – **nur einmal pro Adresse** (sonst wäre unklar, wie viele Nullen wo fehlen) → `2001:DB8:3FA9::D3:9C5A`
Aus der Anzahl der verbleibenden Blöcke (hier 5) ergibt sich die Zahl der Null-Blöcke (8 − 5 = 3). Bei zwei gleich langen Null-Folgen wird die **erste** gekürzt. Nullen **am Ende** eines Blocks dürfen **nicht** entfernt werden (`D000` bleibt `D000`).

### Präfix
Wie CIDR: `2001:DB8:3FA9::/48`. Standard für ein LAN-Subnetz: **/64** → 64 Bit Netzanteil, **64 Bit Interface-ID**.

### Adresstypen
| Typ | Präfix | Entspricht IPv4 | Beispiel | Besonderheit |
|---|---|---|---|---|
| **Loopback** | `::1/128` | 127.0.0.1 | ::1 | eigener Rechner |
| Unspezifiziert | `::/128` | 0.0.0.0 | :: | noch keine Adresse |
| **Global Unicast** (GUA) | `2000::/3` (**2000–3FFF**) | öffentliche Adressen | 2001:db8:21da:7:713e:a426:d167:37ab | weltweit routbar; Aufbau: 48 Bit globales Routingpräfix (öffentlich, vom Provider) + **16 Bit Subnetz-ID** (intern) + 64 Bit Interface-ID |
| **Link-Local** | `fe80::/10` | APIPA 169.254 | fe80::154d:3cd7:b33b:1bc1%13 | **selbst konfiguriert, nicht routbar**, **immer vorhanden** (auch neben anderen Adressen – anders als APIPA); `%13` = **Zonen-ID** (Index der eigenen Schnittstelle) |
| **Unique Local** (ULA) | `fc00::/7` (praktisch **fd**) | private Adressen | fd65:9abf:efb0:1::2 | innerhalb der Organisation routbar, nicht im Internet; 40 Bit zufällige Global-ID + 16 Bit Subnetz-ID + 64 Bit Host |
| **Multicast** | `ff00::/8` | 224.0.0.0/4 | ff02::1 (alle Knoten im Link), ff02::2 (alle Router) | ersetzt Broadcast |
| Site-Local | `fec0::/10` | – | – | **veraltet** |

**Zonen-ID**: Weil jede Schnittstelle eine Link-Local-Adresse aus demselben Bereich fe80::/64 hat, muss beim Ansprechen einer Link-Local-Adresse angegeben werden, **über welche eigene Schnittstelle** gesendet wird (`ping fe80::1%13`). Die Nummer ist der Schnittstellenindex (`Get-NetAdapter` → ifIndex).

**Interface-ID** (64 Bit): per **EUI-64** aus der MAC (FFFE in der Mitte, 7. Bit invertiert), **zufällig** (Privacy Extensions) oder manuell/DHCPv6.

### Autokonfiguration
- **SLAAC** (Stateless Address Autoconfiguration, **statusfrei**): Host bildet eine Link-Local-Adresse, fragt per **Router Solicitation** nach dem Router; der Router antwortet mit einem **Router Advertisement** (Präfix, Gateway). Der Host hängt seine Interface-ID an. **Duplicate Address Detection (DAD)** prüft vorher, ob die Adresse schon vergeben ist. Kein Server führt „Buch“.
- **DHCPv6 statusbehaftet (stateful)**: DHCPv6-Server vergibt Adressen und führt Buch über Leases (wie DHCPv4).
- **Statusfreies DHCPv6 (Mischform)**: Adresse per SLAAC, **Zusatzinformationen** (DNS-Server, Domänenname) per DHCPv6.
Gesteuert über die Flags im Router Advertisement (M = Managed, O = Other).

### Wichtige Protokolle
- **ICMPv6**: ersetzt ICMP und ist **unverzichtbar** (darf nicht komplett blockiert werden – NDP, Router Discovery, PMTU laufen darüber).
- **NDP** (Neighbor Discovery Protocol): ersetzt **ARP**, Router-Erkennung, DAD, Präfixinformationen, Weiterleitungen.
- **MLD** ersetzt IGMP für Multicast.

### Header (40 Byte)
| Feld | Bit | Inhalt |
|---|---|---|
| Version | 4 | 6 |
| Traffic Class | 8 | Priorität (QoS) |
| Flow Label | 20 | Pakete desselben Datenstroms gleich behandeln (Echtzeit) |
| Payload Length | 16 | Länge des Inhalts in Byte |
| Next Header | 8 | Typ des folgenden Headers (TCP, UDP, Extension Header wie **AH/ESP**) |
| Hop Limit | 8 | max. Router-Hops (entspricht TTL) |
| Source / Destination Address | je 128 | Absender / Empfänger |
Mindest-MTU: **1280 Byte** (1,25 KB); mit Jumbogramm-Option bis 4 GB Nutzlast.

### Übergangstechnologien (Legacy – in aktuellen Windows-Versionen standardmäßig deaktiviert bzw. entfernt)
| Technik | Funktionsweise | Einsatz |
|---|---|---|
| **ISATAP** | IPv6 in IPv4 getunnelt innerhalb eines Standorts über einen ISATAP-Router; Adresse enthält IPv4: `fe80::5efe:192.168.1.100` | intern/Intranet |
| **6to4** | 6to4-Router tunneln IPv6 über das IPv4-Internet; öffentliche IPv4 des Routers steckt im Präfix **2002::/16** | Internet, Provider nur IPv4 |
| **Teredo** | IPv6 in **UDP** über IPv4 – funktioniert **hinter NAT**; Komponenten: Teredo-Client, -Server, -Relay, hostspezifisches Relay; Präfix 2001::/32 | Clients hinter NAT, letzte Option |
| **IP-HTTPS** | IPv6 in **HTTPS** getunnelt (ab Server 2008 R2/Win 7) – geht durch fast jede Firewall | DirectAccess |
Heute Standard: **Dual Stack** (beide Protokolle parallel) bzw. beim Provider DS-Lite, NAT64/DNS64.

### NetBIOS und LLMNR
Beide lösen **Namen im lokalen Netz ohne DNS-Server** auf (Anfrage an alle, der Besitzer antwortet) und dienen als Fallback nach DNS. Unterschied: NetBIOS per **Broadcast, nur IPv4**; LLMNR per **Multicast, IPv4 und IPv6**. Beide gelten als unsicher (Poisoning) → siehe Namensauflösung.

## Lab
**Maschinen**: SRV01 und CL01 im selben Hyper-V-Switch. Ziel: ULA-Netz fd00:1:1:1::/64 statisch konfigurieren und testen.

### GUI
1. **SRV01**: `ncpa.cpl` → Ethernet → Eigenschaften → **Internetprotokoll, Version 6 (TCP/IPv6)** → „Folgende IPv6-Adresse verwenden“ → `fd00:1:1:1::10`, Präfixlänge **64** → OK.
2. **CL01**: gleiches Vorgehen mit `fd00:1:1:1::20`/64.
3. Firewall auf beiden: `wf.msc` → Eingehende Regeln → **„Datei- und Druckerfreigabe (Echoanforderung – ICMPv6 eingehend)“** aktivieren.
4. **CL01**: Eingabeaufforderung → `ipconfig` (Link-Local fe80:: und neue ULA sichtbar) → `ping fd00:1:1:1::10`.
5. Link-Local testen: auf SRV01 `ipconfig` Link-Local-Adresse notieren, auf CL01 `ping fe80::…%<eigene Zonen-ID>`.

### PowerShell
```powershell
# Auf SRV01
New-NetIPAddress -InterfaceAlias "Ethernet" -IPAddress fd00:1:1:1::10 -PrefixLength 64
Enable-NetFirewallRule -Name "FPS-ICMP6-ERQ-In"

# Auf CL01
New-NetIPAddress -InterfaceAlias "Ethernet" -IPAddress fd00:1:1:1::20 -PrefixLength 64
Enable-NetFirewallRule -Name "FPS-ICMP6-ERQ-In"
Test-Connection fd00:1:1:1::10
Get-NetIPAddress -AddressFamily IPv6 | Format-Table InterfaceAlias, IPAddress, PrefixLength, PrefixOrigin
Get-NetNeighbor -AddressFamily IPv6      # NDP-Cache (ersetzt arp -a)
netsh interface ipv6 show interfaces     # Zonen-ID/Index der Schnittstellen
Resolve-DnsName www.ihk.de -Type AAAA    # Hat der Host eine IPv6-Adresse?
```

## Einfach

**Das Problem**: Die alten IPv4-Adressen sind **alle vergeben** – wie Telefonnummern, wenn es mehr Menschen als Nummern gibt. **IPv6** ist das neue System mit so vielen Adressen, dass man **jedem Sandkorn der Erde** eine eigene geben könnte.

**Warum sieht die Adresse so komisch aus?** Weil sie so lang ist (128 Bit), schreibt man sie in **Hexadezimal** (0–9 und A–F) in 8 Gruppen: `2001:0DB8:3FA9:0000:0000:0000:00D3:9C5A`. Damit man sich nicht die Finger wund tippt, darf man **abkürzen**:
1. Nullen **vorne** in einer Gruppe weglassen: `00D3` → `D3`.
2. **Einmal** darf man eine Reihe von Null-Gruppen durch `::` ersetzen – wie „usw.“ in einem Satz. Aber nur einmal, sonst weiß niemand, wie viele Nullen wo hingehören.

**Die Adresstypen** – wie Adressen im echten Leben:
- **Global (2000–3FFF)**: deine **richtige Postadresse** – weltweit erreichbar.
- **Unique Local (fd…)**: die **Zimmernummer in der Firma** – nur intern.
- **Link-Local (fe80…)**: der **Spitzname**, den man nur **im gleichen Raum** versteht. Jeder Computer gibt sich den automatisch – immer.
- **Loopback (::1)**: „Ich selbst.“
- **Multicast (ff…)**: eine **Gruppendurchsage**. Einen „Lautsprecher für alle“ (Broadcast) gibt es bei IPv6 nicht mehr.

**Autokonfiguration (SLAAC)**: Der Computer steckt ins Netz und ruft: „Hallo Router, wie heißt die Straße hier?“ Der Router antwortet mit dem Straßennamen (Präfix), und der Computer denkt sich seine eigene Hausnummer aus. Vorher fragt er noch: „Wohnt hier schon jemand mit dieser Nummer?“ (DAD). Ganz ohne DHCP-Server!

**Tunnel (6to4, Teredo …)**: Übergangslösungen, als viele Netze nur IPv4 konnten: Das IPv6-Paket wird in ein IPv4-Paket **eingepackt** wie ein Brief in einen anderen Umschlag. Heute kaum noch nötig.

## Merksatz
- IPv6 = **128 Bit**, **8 × 4 Hex-Ziffern**.
- **`::` nur einmal**, führende Nullen weg, hintere bleiben.
- **2000–3FFF global**, **fd privat**, **fe80 link-lokal**, **ff Multicast**, **::1 Loopback**.
- **Kein Broadcast**, **kein ARP** (→ NDP), **AAAA** im DNS.
- SLAAC = statusfrei, DHCPv6 = statusbehaftet.

## Prüfungsfalle
- `::` zweimal in einer Adresse ist ungültig.
- Nullen am **Ende** eines Blocks dürfen nicht weggelassen werden.
- IPv6 hat **keine Broadcastadresse**.
- Link-Local-Adressen werden **nicht geroutet** und brauchen ggf. die Zonen-ID.
- ICMPv6 komplett blockieren zerstört IPv6 (NDP!).

Computer und Router als Sprechblasen: Router Solicitation → Router Advertisement (Präfix) → Host bildet Adresse → DAD-Frage → Adresse aktiv.

### Tunnel
IPv6-Paket wird in einen IPv4-Umschlag gesteckt, reist durch eine IPv4-Wolke und wird am anderen Ende ausgepackt; Varianten ISATAP, 6to4, Teredo (mit NAT-Schranke), IP-HTTPS.
